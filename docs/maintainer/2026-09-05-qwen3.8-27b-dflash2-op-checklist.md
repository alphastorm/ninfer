## 2. 统一 workload、索引与数值边界

### 2.1 运行 extent

| 符号 | 含义 | 支持范围 |
|---|---|---|
| B | active requests | 1..8 |
| K | 启动选定的 draft count | 1..15，推荐 7 |
| W | proposal/verify 物理 block width | K+1，2..16 |
| T | backbone/target matrix columns | W*B，最大 128 |
| U | mask-head/selector matrix columns | K*B，最大 120 |
| P_b | 每请求可验证 draft extent | 0..K |
| Q_b | target live input columns | P_b+1 |
| A_b | accepted draft count | 0..P_b |
| L_b | provisional output count | A_b+1 |
| N_b | Frontend 最终提交数 | 0..L_b |
| W_c、B_c | context materialization 物理布局 | decode W_c=1..16、B_c=1..8；prefill W_c=1..2048、B_c=1 |
| T_c | context projection columns | W_c*B_c；prefill 最大 2048 |
| N_lane | pending-feature lane capacity | startup-fixed 1..8，且 >=B |
| S_state | StateImage slot capacity | startup-fixed，覆盖本轮 state selectors |

同一 Engine 的物理 W 由选定 K 决定；不能为全部配置计算有效 W=8 或 W=16 来规避扩展。
Proposal attention 可使用 valid_columns=W，target attention/GDN 使用 Q_b，context append
使用 counts=N_b。W_c 是 pending storage/gather extent，不能由 accepted draft count 替代；
all-accept 会提交 K+1 个 target input rows，必须保留最后一行 feature。

性能输入域以 `{(K+1)*B}` 和 `{K*B}` 的实际乘积集合定义。纯矩阵 Op 可以按相同列数去重；
卷积、attention、GDN 和状态 Op 必须保留 W/B 划分以及 device counts。已有 Linear 类 Op 的
任意正 T 合同继续成立；最大 128/120 是本轮产品性能范围，不是这些合同的新上限。

### 2.2 固定模型 geometry 与张量布局

```text
hidden H=5120; MLP I=17408; target feature H_f=25600
draft Q=32*128=4096; K/V=8*128=1024; five local layers; window/capacity=2048
conv groups=320; group width=16; taps=2; sides=2
selector candidates M=16; rank R=256
physical vocab=248320; valid global ids=0..248076; optimized head rows=131072

proposal residual       BF16 [5120,W,B]
finish_delta            BF16 [320,2,W,B]
packed mask hidden      BF16 [5120,U]
candidate ids/scores    I32/FP32 [16,K,B]
projected selector h    BF16 [256,K,B]
drafts / proposal q     I32 [K,B] / FP32 [16,K,B]
target logits           BF16 [248320,W,B]
pending features        BF16 [25600,W,N_lane]
```

Artifact Weight `[N,C]` 表示 `[output rows,input columns]`；runtime Tensor 的 ne[0] 连续。
Base kernel 保留 artifact `[side,tap,channel]=[2,2,5120]`，runtime view 为 `[5120,2,2]`；
codebook 保留 artifact `[vocab,rank]`，runtime view 为 `[256,248320]`。这些固定 8/16/256
等模型维度不能随运行 W/K 一起替换。

### 2.3 保持的数学与实现自由度

- Dynamic convolution 仅在当前 request block 内跨相邻位置，位置零没有 previous tap；
  finish 消费同一 prepare 的 output-side delta，无跨轮卷积状态。
- Proposal SWA 为 `abs(key_position-query_position)<2048`；当前 block 的有效 query 互相
  可见。Q/K 使用 plain head RMSNorm 和 theta=1e7 的 full-D128 split-half 1-D RoPE。
- Final norm-pack 跳过 anchor；top-16 使用 score 降序、同分 global-id 升序。Optimized
  head 的 row id 先映射为 global id，再供 selector 使用。
- Selector 是实际前驱条件下的逐位 walk；保留实际抽样的 FP32 q。逐 row、部分预计算、
  完整 lattice 均可作为同一 Op 的内部方案，不能换成独立逐位置 unary argmax 或 Viterbi。
- Sparse accept 使用实际 q 的 p/q rejection 和 `(p-q)+` correction；N 而非 P/A/L 决定
  最终持久状态提交。Proposal RNG purpose 与 target accept/correction/bonus 分离。
- Norm/conv prepare、projection/conv/residual、norm/RoPE、norm/pack、projection/top-k、
  selector walk 和五层 context materialization 保持闭合 public 边界。Private staging、
  reduction、tiling、launch 数由 qualified route 决定，不要求每个融合 Op 只有一个 kernel。
- Oracle 从 represented public inputs 及精确解码的 stored weights 计算完整公式；不可观察
  中间精度作为 implementation profile。OP-07 已去掉 raw K 的额外语义舍入；最终 BF16 K、
  `FP16_RNE(BF16)` V storage cast、public BF16 outputs 和实际 FP32 q 保持各自边界。

## 3. 必须修正合同和实现的 Ops

### OP-01 — rmsnorm_dynamic_grouped_conv_prepare

合同：[dynamic_grouped_conv.h](../../include/ninfer/ops/dynamic_grouped_conv.h)。落点：
`src/ops/wrapper/dynamic_grouped_conv.cpp`、`src/ops/dynamic_grouped_conv/bf16/`。

已修正的问题：合同和 wrapper 固定 W=8；plan 仅按 B 选择 split-K。Partial kernel 将八列 MMA tile
与 request batch 绑定，reduce 的 128 threads 正好只处理 8*16 个位置/通道。

**实际实现与复杂度：** reduce 从 15 个 exact-W 实例改成容量 8/16 的两个布局，所有公开地址和 previous tap 使用运行时 W。Partial 合并 C24/C40 后保留 6 个 MMA tile；两阶段合计由 23 个实例降至 8 个。三节点执行和 split/scratch 规则保持不变。

**验收：** 既有完整 FP64 norm→projection→conv 测试通过全部 120 个 W/B，覆盖 prepared/finish_delta、request 边界、guards、workspace 和同址 Graph。测试入口不变，无需新增重复 fixture。相同 cold Graph 基准（RTX5090/sm_120a/CUDA13.1，warmup4/repeat25）比较全部 120 点：median 差值的中位数为 0µs；W2/B1 为 15.648→15.616µs，W8/B8 为 25.824→25.600µs，W16/B8 为 32.000→32.000µs。个别点约 2µs 档位变化，不主张全域提速。

**结论：** 完成本项清理；保留决定 MMA 并行度的有限 tile，不继续追逐局部交叉点。合同、输出数值判据与最大 scratch 2,621,440 B 均不变。

### OP-02 — linear_dynamic_grouped_conv_add

合同同 OP-01。落点：`src/ops/dynamic_grouped_conv/w8/` 和公共 wrapper。

已修正的问题：两个 C=4096/17408 profile 的 scratch、实例表和 dispatch 都基于 8B；finish 用
`col & 7` 判断 previous tap。旧 B-specific cache/K-warp 表不能覆盖新 W/B geometry。

**实际实现与复杂度：** 消除两套 T1..64 exact 表，复用现有支持 live-column 屏蔽的 W8 MMA。T≤88 按实际 8-column accumulator 容量选择 8..88；两种 C 合计 22 个实例，替代此前 128 个 exact 实例和 7 个 tiled 实例。T≥89 统一使用已有 K128 MMA，删除 C4096/T89..96 的 C32 特例；主 route 从六种收敛为两种。没有新增或修改共享 contraction，finish 保持运行时 W。

**验收：** 现有两种 C、共 240 个 W/B 的完整 FP64 projection→conv→residual 测试通过，包括原地 residual、request 边界、guards、Graph 和 workspace。相同 cold Graph（RTX5090/sm_120a/CUDA13.1，warmup4/repeat20）测量 240 点，两格式 median 差值的中位数分别为 0/−0.032µs。W16/B8：C4096 62.720→62.592µs，C17408 238.848→238.848µs；W8/B1 为 21.760→21.696 / 68.864→68.832µs。

**结论与取舍：** 完成本项清理。Runtime mask 和收敛上端 route 在部分点有代价：本轮最大 median 增量约 2.24µs，C4096/T91 为 58.432→60.672µs；未声称全部点提速，也不为这类局部差异恢复 exact-T 表。保留两种计算机制及自然 MMA 容量，零额外 launch，scratch 仍为 5120*T*2 B。

最终两个 C profiles 均在 T<=64 使用 exact-small-T，65..72/73..80/81..88 使用

可见集仍严格为 `abs(key_position-query_position)<window`，包含所有有效临时 query K/V，
不把 envelope 或推荐 W=8 当作数学限制。Cached K 按 BF16、cached V 按实际 FP16 codec
值解释；query K/V 是独立的 BF16 输入，context 全程只读。

旧 split 路线把未归一化 numerator 写成 BF16，再归并、归一化并再次转 BF16。在新增的
短实际 context / 宽 Graph envelope 与 ragged batch 用例中，这个中间舍入产生额外误差。
现改用 FP32 partial numerator，m/l 仍为 FP32，最终只写 BF16 out。共享 contraction
仅增加 FP32/BF16 partial storage 的编译期选择；已有 growing-context Attention 保留其
BF16 specialization，没有复制或改变共享的 QK/Softmax/PV 算法。零 valid 的 direct 路线
也修正为不依赖无效物理尾部 `positions[0]`；split 路线由归并 kernel 精确写零，无需额外选择 L。

验收仍使用完整、独立的 FP64 数学 oracle，没有仿制 FP16 P/V、partial 或输出舍入。
旧 gross cap `3e-4 + 0.003*max_abs(reference)` 对部分正确 BF16 输出也过紧：例如
reference=-0.529292 对应最近 BF16=-0.53125。BF16 最终舍入的相对误差上界约 1/256，
新统一 criterion 为 rL2<=0.0023、gross<=`3e-4 + 0.0045*max_abs(reference)`，拒绝非有限
结果；gross 显式包含最终 BF16 和 FP16 P/V 算术误差预算，rL2 从旧 0.00395 收紧。
旧 BF16 partial 路线在此 criterion 下仍失败；最终 FP32 路线的全部 352 个比较通过，
最大 rL2=0.001953125、gross/limit=0.755 以下。

比较 32/64-key tile、4/8/16/32 splits、1/4 merge warps、direct/split 后，2048 路线
保留 KeyBlock=32，merge 改用 4 warps；每个 partial CTA 的 warps=`ceil(W/4)`。
Direct 上限在 W=9..16 且 B=6..8 时为 128，其余为 96。Split 上限如下，最后再限于
`max(1,ceil(min(max_context,2047)/32))` 个实际可能存在的 context tiles：

| W | 基础 split 上限 | 较短 context 的限制 |
|---|---|---|
| 1..4 | B=1..2:32；B=3..6:16；B=7..8:8 | 无附加限制 |
| 5..8 | B=1:32；B=2:16；B=3..8:8 | B>=6 时再限于 max(4,floor(context_tiles/4)) |
| 9..16 | B=1..2:16；B=3..5:8；B=6..8:4 | B=2 时再限于 max(4,floor(context_tiles/2))；B>=3 时除数为4 |

Direct 为 1 kernel、零 scratch；split 为 2 kernels。Workspace query 扫描请求的 W 区间，
正确处理 4/5、8/9 等上限下降点，不能仅查询区间最大 W。2048 profile 的全域最大 scratch

### 4.1.6 OP-14 — cyclic KV prefix append qualification

合同保留 BF16 `[128,8,T,B]`、任意正物理 T、B=1..8；`counts[b]` 和 host envelope 决定
实际提交前缀，不能从物理 T、推荐 K=7 或 draft backbone W 推导 commit count。K 精确复制
原始位模式，V 按 `FP16_RNE(BF16 input)` 写入；capacity=2048/4096，lane、ring padding 和
absolute-position wrap 由显式 cache view/metadata 决定。明确零 count 不消费 positions/K/V，
也不要求 `positions[0]` 表示有效起点；frontier 仍由调用方拥有。

原 cyclic kernel 每线程复制16元素、每256-thread CTA处理四个 token，短前缀的 CTA 数偏少。
现统一每线程一个8元素/16-byte向量，删除 cyclic 双向量串行路径；在获取 lane、position
或 K/V 之前按 device count 退出无效线程。`max_count*B<=128` 使用64-thread CTA（半个
token/CTA），更大 envelope 使用128-thread CTA（一个 token/CTA）。分块与 stride 分别
取自 max_count 和物理 T，故固定宽 buffer 的短前缀不会多启动按物理宽度计算的 CTAs。
2048/4096 使用同一方案。比较了8/16元素向量和32/64/128/256 threads的七个有效候选，
以及单请求17..2048前缀；较大的前缀也选择8元素路径。Op始终零 scratch；max_count>0
为一个 kernel，max_count=0 无 kernel，后者与 device count=0但envelope>0的单-kernel
空提交不同。

独立 exact oracle 从输入位模式计算所有目的地址和 FP16 RNE codec，逐字节比较整个
cache（含 padding、未选 lanes、未提交尾），不拿另一个 GPU 路径作参考。新增180个
用例覆盖全部128个 Wc=1..16/B=1..8组合；混合 counts=0/1/短/满、奇数宽度、lane重排、
跨 ring 边界与多圈、持久 cache 连续更新均通过。Graph在相同地址上修改 counts、lanes、
positions、K/V后重放；NaN输入尾和负数position尾不能污染cache；所有输入和guards不变。
满W16/B8用例枚举全部有限BF16位模式，包含signed zero、FP16下溢/次正规/溢出等codec边界。
另覆盖physical T=16/upper=7、T=4097/upper=16，以及17/65/127/128/129/2048前缀；
4096 profile覆盖Wc=1/3/8/9/16/17、B=1/8和4096满前缀。原paged/full各storage回归也通过。

### 4.1.7 OP-15 — LinearPair 依赖退出复核

### 4.1.8 OP-16 — ragged feature-prefix preparation qualification

公开 Op 继续支持正 W 和8元素对齐的 D，不按 K=7 或 W=8 收窄 generic gather。
DFlash2 用 `[25600,W_c,N_lane] -> [25600,W_c,B]`；N=ends-starts 决定复制的输入前缀，
N=W_c=16时完整保留all-accept的最后一行。source列/lanes可以有显式stride；输出
BF16位模式精确复制，尾部写BF16 +0。Positions对有效行写start+j，对尾部重复最后live
position；N=0重复start。Counts精确写N。三个输出彼此独立且不覆盖输入；只读输入允许
相互别名，没有为了并行实现而禁止合法的starts/ends共用。

原性能路径每列只有一个128-thread CTA，逐线程循环搬运完整feature列。比较11个block/
feature-tile配置及flat/3D grid后，统一每CTA处理1024个BF16元素（2KiB），128个线程各
搬运一个16-byte向量。Grid的x/y/z分别表示column、batch、feature tile，避免kernel内
对tile数做整数除法；Z受CUDA grid上限约束时通过grid stride覆盖更大的generic D。
Positions只由该列的feature tile 0/thread 0写入，counts再限定column 0，避免metadata
多写入者。所有模式均为1 kernel、零scratch；N=0仍必须清零完整输出并生成metadata。

新增独立 `ninfer_prepare_ragged_prefix_test`，从scatter测试移出该Op的组合调用，保留
scatter自身检查。Exact oracle逐元素计算source地址、前缀、position和count，不调用另一个
GPU Op。全部128个W_c=1..16/B=1..8组合通过，另测zero/one/full前缀、奇数宽度、八个
lane置换、column/lane padding、任意BF16位模式（含NaN payload），以及Graph重放时
同时改变source、lanes、starts、ends。输出和metadata从poison完全覆盖；source/输入
metadata及所有guards保持不变；zero-prefix Graph也覆盖starts和ends别名。D=8/24/16384
及W_c=17回归通过。`ninfer_scatter_test`通过。

性能证据：RTX5090、CUDA13.1、Release/sm_120a，完整公开Op；D=25600的全部W_c/B组合
分别测full/one/ragged/zero的cold单次Graph和warm 32-call Graph，共1024点，另有eager、
D=16384与W_c=17 anchors。Cold每次flush256MiB；warm按每次调用归一化，warmup=10、
repeat=100。代表median（μs）：

| Wc / B / 前缀 | 旧cold → 新cold | 旧warm → 新warm |
|---|---:|---:|
| 1 / 1 / full | 9.440 → 3.360 | 3.602 → 1.332 |
| 8 / 8 / full | 11.520 → 7.328 | 3.901 → 2.272 |
| 16 / 8 / full | 13.632 → 9.472 | 4.138 → 3.433 |
| 16 / 8 / ragged | 13.568 → 7.456 | 4.252 → 3.287 |
| 16 / 8 / zero | 5.376 → 5.376 | 3.050 → 3.051 |

Cold部分小shape的p95仍可跨越约3.36/5.4μs区间；表中是median，不代表尾延迟保证。

父张量column/lane stride的row-sliced view；C是独立lane容量，caller提供互异lanes与
不重叠的存储列。五次调用分别写 `[0,5120)`、`[5120,10240)`、…、`[20480,25600)`，
均为exact BF16 bit copy，其他slice、无效列、未选lane和padding保持原值。

实现将每列一个CTA改成128-thread / 2KiB feature tile，grid为`[W,B,ceil(D/1024)]`，
并保留超过CUDA grid.z上限时的feature grid-stride loop。各CTA先读有效列数，空前缀不读
源数据或写目标。独立column/lane stride仍用于寻址；一次public Op为一个kernel、零scratch。
已比较六种64/128/256 threads与feature tile组合；选定128/128的向量tile方案兼顾
full、ragged与空前缀成本。统一tile循环与逐线程tail分开，保留较快的实测实现。

新增 `ninfer_scatter_bf16_batch_test`：163个fixture通过，覆盖D5120全部W=1..16/B=1..8，
五个feature offset、每次slice写入后的整个目标池exact检查、任意BF16位模式、lane重排、
有效列0/1/W-1/W、物理lane可保留16列的padding、column padding、输出/输入guards与metadata
只读。Graph捕获五次调用后，在同地址修改源数据、lanes、counts并重放，检查保留旧池内容。
补D8/24/16384、W17以及现有35B的D2048/八个feature slices；原scatter/extract回归通过。

新 `ninfer_scatter_bf16_batch_bench` 测五个独立源写同一父池的五次public capture，总耗时
不除以五。RTX5090 / sm_120a / CUDA13.1，warmup10/repeat100；全部W=1..16/B=1..8 ×
full/one/ragged/zero × cold Graph/warm Graph32，共1024点，另有eager/profile smoke。
Graph32重复整组capture，160 kernel nodes，时间除以32；cold只在整段之前flush 256MiB。

  改为显式 K/W/B，删除固定推荐宽度是唯一合法输入的断言，不建立兼容 aliases。

  query 上界。Capacity 取区间内所有可达 routes 的最大值，不能只测最大 K/B 一个点。
